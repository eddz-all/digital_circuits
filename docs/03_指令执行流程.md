# 指令执行流程

## 先看结论

```text
输入加载不计数
输出倒出不计数
cnt 只统计 worker 跑 ROM 指令的时间
```

当前 FFT 程序的计数结果：

```text
cnt_cycles = 22
```

如果 ILA 用十六进制显示：

```text
cnt_test = 00016
```

这里的 `00016` 是十六进制，等于十进制 22。

## 程序启动前

外层 `mcu_fft_system` 先做输入准备：

| 步骤 | 做什么 |
| --- | --- |
| 1 | 从 `test_ROM[128..143]` 读 16 个 16-bit 输入 |
| 2 | 每两个 16-bit 打包成一个 32-bit word |
| 3 | 按 `BITREV_ORDER` 写入 `bank0[0..7]` |
| 4 | 输入全部写完后释放 worker reset |

这个阶段 worker 一直保持 reset。

所以这段不算进 `cnt`。

## 计数怎么开始

输入写完后，外层进入 `S_START_RUN`：

```text
cnt_start = 1
core_rst  = 0
```

下一拍开始，worker 真正从 reset 出来，从 `pc00` 取第一条指令。

这就是计数第 1 拍。

## 四个 worker 怎么跑

```text
PROGRAM_ID = 0
ACTIVE_CORES = 4
```

四个 worker 同时启动：

| worker | 跑的程序 |
| --- | --- |
| worker0 | `FFT_ROM_W0` |
| worker1 | `FFT_ROM_W1` |
| worker2 | `FFT_ROM_W2` |
| worker3 | `FFT_ROM_W3` |

每个 worker 都有自己的：

```text
pc_fetch_reg
寄存器组
执行状态机
指令 ROM 入口
```

它们不是轮流跑，而是四个同时跑。

## 前两拍在干什么

worker 刚启动时，流水还没装满。

| 计数拍 | worker 状态 | 做什么 |
| --- | --- | --- |
| 1 | `S_FETCH` | 用 `pc_fetch_reg=0` 取 `pc00`，放进译码级 |
| 2 | `S_DECODE` | 把 `pc00` 放进执行级，同时取后面的指令 |
| 3 | `S_RUN` | 第一条有效指令开始退休 |

所以不是第 1 拍就执行完 `pc00`。

前两拍是取指、译码的流水填充。

## 第 3 拍以后

进入 `S_RUN` 后，普通情况每拍做三件事：

```text
1. 执行当前 exec_* 指令
2. 把 dec_* 指令推进执行级
3. 从 ROM 取下一条指令进入译码级
```

如果当前指令和下一条指令能双发：

```text
一拍退休两条指令
PC += 8 bytes
```

如果不能双发：

```text
一拍退休一条指令
PC += 4 bytes
```

如果遇到 `SMUAD/SMUSD`：

```text
暂停普通 S_RUN
进入 DSP 多周期状态
做完再回到 S_RUN
```

## 为什么看 worker1 和 worker3

系统结束条件是：

```text
四个 active worker 都到达 ROM 末尾的标准 A32 `B .` 完成哨兵
```

worker0 和 worker2 较短，后面有 `NOP` 等待。

最长的是 worker1 和 worker3，因为它们后半段有：

```asm
SMUAD / SMUSD
SMUSD / SMUAD
ASR
PKHBT
SADD16
SSUB16
STR
STR
```

所以 22 拍由 worker1/worker3 决定。

## 22 拍展开

下面按 worker1/worker3 的最长路径展开。

| 计数拍 | 发生的事 |
| --- | --- |
| 1 | `S_FETCH`，取 `pc00` |
| 2 | `S_DECODE`，`pc00` 进入执行级 |
| 3 | 双发 `pc00 MOV r0,#0` 和 `pc01 MOV r1,#91` |
| 4 | 执行 `pc02 PKHBT`，生成 `+91/+91` |
| 5 | 执行 `pc03 SSUB16`，生成 `-91/-91` |
| 6 | 双发 `pc04 LDR` 和 `pc05 LDR` |
| 7 | 双发 `pc06 SADD16` 和 `pc07 SSUB16` |
| 8 | 双发 `pc08 STR` 和 `pc09 STR` |
| 9 | 双发 `pc10 LDR` 和 `pc11 LDR` |
| 10 | 执行 `pc12 SSAX` |
| 11 | 双发 `pc13 SADD16` 和 `pc14 SSUB16` |
| 12 | 双发 `pc15 STR` 和 `pc16 STR` |
| 13 | 双发 `pc17 LDR` 和 `pc18 LDR` |
| 14 | 执行 `pc19 SMUAD/SMUSD`，启动 DSP 多周期，第一条 DSP 做 `mul_s16_stage1` |
| 15 | `S_DSP_MUL`，第一条 DSP 做 `mul_s16_stage2`，同时抓取第二条 DSP 并做 `mul_s16_stage1` |
| 16 | `S_DSP_PAIR_MUL_ACC`，第一条 DSP 做加减，第二条 DSP 做 `mul_s16_stage2` |
| 17 | `S_DSP_PAIR_WB_ACC`，写回第一条 DSP，并计算后面的 `ASR` 结果 |
| 18 | `S_DSP_PAIR_WB`，写回第二条 DSP，同时退休 `ASR` |
| 19 | 执行 `PKHBT`，把移位后的结果重新打包 |
| 20 | 双发 `SADD16` 和 `SSUB16` |
| 21 | 双发 `STR` 和 `STR` |
| 22 | 执行/观察到 `B .` 完成哨兵，最长 worker 到达标准自跳转 |

第 22 拍之后，顶层已经寄存到所有 active worker 的 `B .` 完成哨兵，外层看到
`core_halted=1` 这个历史端口名，拉高：

```text
cnt_stop = 1
```

计数停止。

## 22 拍为什么不是指令条数

worker1/worker3 的 ROM 有 28 条左右的可见指令，但计数只有 22 拍。

原因是：

| 机制 | 影响 |
| --- | --- |
| 流水 | 取指、译码、执行重叠 |
| 双发射 | 某些相邻指令一拍退休两条 |
| DSP 配对 | 两条相邻 DSP 指令共用一段多周期路径 |
| ASR 合并 | DSP 配对末尾可以同时退休相关 `ASR` |

所以：

```text
22 拍 = 启动填充 2 拍 + 最长 worker 的退休路径
```

不是简单地数 ROM 里有多少条指令。

## 结束后发生什么

计数停止后，外层进入 `S_DUMP_WRITE`：

| 步骤 | 做什么 |
| --- | --- |
| 1 | 从 `bank1[0..7]` 读 8 个 32-bit 输出 word |
| 2 | 每个 word 拆成低 16 位和高 16 位 |
| 3 | 写入 `verify_RAM[0..15]` |

这个阶段也不计入 `cnt`。

## 一句话答辩说法

```text
输入先由外层装入 bank0，装完后释放四个 worker 并启动计数。计数第 1、2 拍用于取指和译码填充，从第 3 拍开始退休指令。worker1 和 worker3 路径最长，普通指令靠流水和双发射推进，SMUAD/SMUSD 进入两级乘法的 DSP 配对多周期路径，最后第 22 拍到达标准 A32 `B .` 完成哨兵，所以 cnt_cycles 是 22，也就是 ILA 十六进制显示的 00016。
```
