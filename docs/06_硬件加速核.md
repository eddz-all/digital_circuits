# 硬件加速核

## 当前版本

```text
参考版本：MCU_4cores_muticycle_v3
提交：5cc0972 MUL
```

## 我们的硬件加速核是什么

```text
SMUAD/SMUSD 使用的 16-bit 乘法执行单元
```

它不是 FFT 黑盒。

它是 worker 执行 ARM-DSP 风格指令时调用的数据通路。

## 为什么符合要求

老师 PPT 里举的是：

```text
硬件加速核：乘法器
```

我们这里对应的是：

```text
SMUAD/SMUSD 指令 -> 16-bit 乘法器 -> 乘积加减 -> 写回寄存器
```

程序员能在汇编里看到：

```asm
SMUAD r7, r6, r3
SMUSD r8, r6, r4
```

所以它是指令可见的执行单元，不是隐藏的 FFT 专用硬件。


## 乘法器怎么做

v3 没有直接写：

```vhdl
signed(a) * signed(b)
```

而是手写了两级 16-bit signed 乘法。

第一级：

```text
mul_s16_stage1
```

做这些事：

```text
1. 取 a、b 的绝对值
2. 记录结果符号 negative
3. 生成 16 个部分积 pp0..pp15
4. 用 CSA 压缩成 t0..t5
```

第二级：

```text
mul_s16_stage2
```

做这些事：

```text
1. 继续用 CSA 压缩 t0..t5
2. 最后做一次加法得到 32-bit 乘积
3. 根据 negative 决定是否取负
```

## SMUAD

```asm
SMUAD rd, rn, rm
```

含义：

```text
lo = signed(rn[15:0])  * signed(rm[15:0])
hi = signed(rn[31:16]) * signed(rm[31:16])
rd = lo + hi
```

## SMUSD

```asm
SMUSD rd, rn, rm
```

含义：

```text
lo = signed(rn[15:0])  * signed(rm[15:0])
hi = signed(rn[31:16]) * signed(rm[31:16])
rd = lo - hi
```

## 单条 DSP 指令流程

```text
S_RUN
  启动 SMUAD/SMUSD
  对 lo 和 hi 两路乘法做 mul_s16_stage1

S_DSP_MUL
  对 lo 和 hi 两路乘法做 mul_s16_stage2
  得到 dsp_prod_lo 和 dsp_prod_hi

S_DSP_ACC
  SMUAD 做加法
  SMUSD 做减法

S_DSP_WB
  写回 rd
```

## 两条 DSP 配对流程

如果两条相邻 DSP 指令没有寄存器冲突：

```asm
SMUAD r7, r6, r3
SMUSD r8, r6, r4
```

可以走配对路径：

```text
S_RUN
  第一条 DSP 做 mul_s16_stage1

S_DSP_MUL
  第一条 DSP 做 mul_s16_stage2
  第二条 DSP 做 mul_s16_stage1

S_DSP_PAIR_MUL_ACC
  第一条 DSP 做加减
  第二条 DSP 做 mul_s16_stage2

S_DSP_PAIR_WB_ACC
  写回第一条 DSP
  第二条 DSP 做加减

S_DSP_PAIR_WB
  写回第二条 DSP
```

## 和普通 ALU 的关系

普通 ALU 负责：

```text
ADD
SUB
AND
ORR
MOV
ASR
LDR/STR 地址选择
B/BL/MOV pc,lr
```

硬件加速核重点负责：

```text
SMUAD
SMUSD
```

它们都写在同一个 worker 里，没有单独拆成 `alu.vhd` 或 `multiplier.vhd`。

答辩时可以说：

```text
ALU 和硬件加速核没有拆成独立文件，而是内嵌在 worker 的执行级中。
普通指令走普通 ALU 路径，SMUAD/SMUSD 走专门的两级 16-bit 乘法路径。
```

## 不使用 FPGA DSP48

代码里有：

```text
attribute use_dsp of dsp_prod_lo  is "no";
attribute use_dsp of dsp_prod_hi  is "no";
attribute use_dsp of dsp2_prod_lo is "no";
attribute use_dsp of dsp2_prod_hi is "no";
```

综合/实现报告：

```text
utilization_report_210.txt
DSPs = 0
```

所以这里的 DSP 指：

```text
ARM-DSP 风格指令
```

不是：

```text
Xilinx DSP48 物理资源
```

## 不要这样说

不要说：

```text
我们做了 FFT 专用加速器
SMUAD/SMUSD 使用了 FPGA DSP48
乘法器自动完成 FFT butterfly
```

应该说：

```text
我们在 MCU worker 内部为 SMUAD/SMUSD 指令实现了两级 16-bit 乘法执行单元。
FFT 程序通过汇编指令显式调用这个执行单元，因此仍然是指令驱动的 MCU。
```
