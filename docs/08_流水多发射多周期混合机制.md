# 流水多发射多周期混合机制

## 先回答会不会乱

不会乱。

原因是 worker 每一拍只有一个总控制状态：

```text
S_FETCH
S_DECODE
S_RUN
S_DSP_MUL
S_DSP_ACC
S_DSP_WB
S_DSP_PAIR_MUL_ACC
S_DSP_PAIR_WB_ACC
S_DSP_PAIR_WB
```

普通指令、多发射、DSP 多周期不是同时乱跑。

它们的关系是：

```text
普通指令只在 S_RUN 发射
双发射也只在 S_RUN 判断
DSP 指令从 S_RUN 进入 DSP 状态
进入 DSP 状态后，普通 S_RUN 发射暂停
DSP 做完后再回到 S_RUN
```

## 三个概念

| 名称 | 在本工程里的意思 |
| --- | --- |
| 流水 | 当前指令在执行级，下一条在译码级，再下一条在取指侧准备 |
| 多发射 | 某些安全的相邻两条指令可以在同一个 `S_RUN` 执行 |
| 多周期 | `SMUAD/SMUSD` 不在一拍内完成，会进入 DSP 多周期状态 |

## 不是完整五级流水

本工程不是标准的：

```text
IF / ID / EX / MEM / WB
```

更准确地说，它是：

```text
取指侧 + 译码寄存器 + 执行寄存器 + 写回前递 + DSP 多周期状态
```

对应信号：

| 阶段 | 主要信号 | 作用 |
| --- | --- | --- |
| 取指侧 | `instr_word`, `fetch_dec_*` | 当前 `pc_fetch_reg` 对应的 ROM 输出 |
| 相邻取指侧 | `instr_pair_word`, `fetch_pair_dec_*` | `pc_fetch_reg + 4` 对应的 ROM 输出 |
| 译码级 | `instr_reg`, `dec_*` | 下一条准备执行的指令 |
| 执行级 | `exec_instr`, `exec_*` | 当前正在执行的指令 |
| 写回 | `rf_wb_*`, `rf_wb2_*` | 把结果写回寄存器，并给后续指令前递 |
| DSP 临时级 | `dsp_*`, `dsp2_*` | 保存 DSP 多周期中间值 |

## 取指侧为什么能看两条

worker 里有两个 ROM 读取路径：

```text
pc_fetch_reg      -> 当前取指
pc_fetch_reg + 4  -> 下一条取指
```

所以硬件同时能看到：

```text
当前待取指令
下一条相邻指令
```

当前上板版本中，ROM 同时给出：

```text
当前指令字 instr_word
当前指令预译码 fetch_dec_*
下一条指令字 instr_pair_word
下一条指令预译码 fetch_pair_dec_*
当前 pair_kind
下一条 next_pair_kind
```

这就是双发射判断的基础。

## 初始三拍

复位释放后，一个 worker 大致这样启动：

| 拍 | 状态 | 做什么 |
| --- | --- | --- |
| 1 | `S_FETCH` | 把 `pc0` 指令装进译码级 |
| 2 | `S_DECODE` | 把 `pc0` 指令装进执行级，同时取 `pc1` |
| 3 | `S_RUN` | 开始执行 `pc0` |

从第 3 拍开始，worker 进入稳定执行状态。

## 普通单发射

假设当前没有双发射，也不是 DSP，也不是分支。

某一拍开始前：

```text
exec_* = pcN      当前执行
dec_*  = pcN+1    下一条
取指侧 = pcN+2    再下一条
```

这一拍 `S_RUN` 做三件事：

```text
1. 执行 pcN
2. 把 pcN+1 推到执行级
3. 把 pcN+2 推到译码级
```

这一拍结束后：

```text
exec_* = pcN+1
dec_*  = pcN+2
pc_fetch_reg 指向 pcN+3
```

所以普通单发射时：

```text
每拍执行一条
pc 每拍加 1
```

## 普通单发射示意

| 拍 | 执行级 | 译码级 | 取指侧 |
| --- | --- | --- | --- |
| T | `pcN` | `pcN+1` | `pcN+2` |
| T+1 | `pcN+1` | `pcN+2` | `pcN+3` |
| T+2 | `pcN+2` | `pcN+3` | `pcN+4` |

## 双发射发生在哪里

双发射只在：

```text
S_RUN
```

判断。

双发射使用两级指令：

```text
exec_*  = 第一条
dec_*   = 第二条
```

如果 `pair_kind` 有效，这一拍同时执行：

```text
exec_* 对应的指令
dec_* 对应的指令
```

执行完后直接跳过两条：

```text
pc = pc + 2
```

## 哪些指令能双发射

| 双发类型 | 条件 |
| --- | --- |
| `MOV_IMM + MOV_IMM` | 两条写不同寄存器 |
| `LDR + LDR` | 同 bank，写不同寄存器 |
| `STR + STR` | 同 bank，写不同 idx |
| `SADD16 + SSUB16` | 源寄存器相同，目的寄存器不同 |

只有这些白名单类型能双发射。

其他组合一律单发射。

## 双发射示意

某一拍开始前：

```text
exec_* = pcN
dec_*  = pcN+1
取指侧 = pcN+2
相邻取指侧 = pcN+3
```

如果 `pcN` 和 `pcN+1` 能双发：

这一拍执行：

```text
pcN
pcN+1
```

这一拍结束后：

```text
exec_* = pcN+2
dec_*  = pcN+3
pc_fetch_reg 指向 pcN+4
```

所以双发射时：

```text
一拍执行两条
pc 加 2
```

## 双发射为什么安全

双发射不是执行级临时乱猜。

ROM 预译码时已经算出：

```text
pair_kind
```

`pair_kind` 会检查：

```text
opcode 是否属于双发白名单
是否 illegal
写寄存器是否冲突
访存 idx 是否冲突
SIMD 源寄存器是否一致
```

如果不安全：

```text
pair_kind = 000
```

worker 就按单发射执行。

## 双发射写回

双发射最多产生两个写回结果：

```text
wb
wb2
```

例如：

```asm
SADD16 r10, r5, r6
SSUB16 r11, r5, r6
```

同一拍：

```text
wb  写 r10
wb2 写 r11
```

因为双发条件要求目的寄存器不同，所以不会同拍写同一个寄存器。

## LDR 双发射

例子：

```asm
LDR r5, A[2]
LDR r6, A[3]
```

同一拍：

```text
读口 1 读 A[2] -> r5
读口 2 读 A[3] -> r6
```

要求：

```text
同 bank
rd 不同
```

## STR 双发射

例子：

```asm
STR r10, B[2]
STR r11, B[3]
```

同一拍：

```text
写口 1 写 B[2]
写口 2 写 B[3]
```

要求：

```text
同 bank
idx 不同
```

## DSP 单条多周期

`SMUAD/SMUSD` 不在一拍完成。

单条 DSP 路径：

```text
S_RUN
S_DSP_MUL
S_DSP_ACC
S_DSP_WB
S_RUN
```

每个状态做什么：

| 状态 | 做什么 |
| --- | --- |
| `S_RUN` | 发现 `SMUAD/SMUSD`，启动 `mul_s16_stage1` |
| `S_DSP_MUL` | 执行 `mul_s16_stage2`，得到两个 16-bit 乘法结果 |
| `S_DSP_ACC` | 对两个乘积做加法或减法 |
| `S_DSP_WB` | 写回 DSP 结果 |
| `S_RUN` | 回到普通执行 |

## DSP 状态为什么不会和普通发射乱掉

进入 DSP 状态后：

```text
run_ctrl_exec = 0
run_ctrl_rf   = 0
run_ctrl_mem  = 0
run_ctrl_pair = 0
```

意思是：

```text
普通执行不发射
普通双发射不判断
普通访存写使能不打开
```

所以 DSP 多周期期间，不会又同时乱执行普通指令。

## DSP 配对

如果两条 DSP 连在一起，并且第二条不依赖第一条结果，可以走 DSP 配对路径。

例子：

```asm
SMUAD r7, r6, r3
SMUSD r8, r6, r4
```

第一条 DSP 在 `S_RUN` 启动时，会检查译码级的下一条：

```text
下一条是否也是 SMUAD/SMUSD
下一条是否 illegal
下一条 rn/rm 是否不依赖第一条 rd
下一条 rd 是否不等于第一条 rd
```

满足条件：

```text
dsp_pair_ready = 1
```

## DSP 配对状态

DSP 配对路径：

```text
S_RUN
S_DSP_MUL
S_DSP_PAIR_MUL_ACC
S_DSP_PAIR_WB_ACC
S_DSP_PAIR_WB
S_RUN
```

每个状态做什么：

| 状态 | 做什么 |
| --- | --- |
| `S_RUN` | 第一条 DSP 做 `mul_s16_stage1`，并把第二条 DSP 推进执行级 |
| `S_DSP_MUL` | 第一条 DSP 做 `mul_s16_stage2`；第二条 DSP 做 `mul_s16_stage1` |
| `S_DSP_PAIR_MUL_ACC` | 第一条 DSP 做加减；第二条 DSP 做 `mul_s16_stage2` |
| `S_DSP_PAIR_WB_ACC` | 写回第一条 DSP；第二条 DSP 做加减 |
| `S_DSP_PAIR_WB` | 写回第二条 DSP，必要时合并写回相关 `ASR` |

## DSP 后面的 ASR 合并

FFT 里有这种序列：

```asm
SMUAD r7, r6, r3
SMUSD r8, r6, r4
ASR   r7, r7, #7
```

`ASR r7, r7, #7` 依赖第一条 DSP 的 `r7`。

硬件在 DSP 配对写回阶段会判断：

```text
当前 exec_op 是 ASR
ASR 的 rn 等于第一条 DSP 的 rd
ASR 的 rd 不等于第二条 DSP 的 rd
```

满足时：

```text
第一条 DSP 结果先移位
第二条 DSP 结果正常写回
ASR 结果通过第二条写回通路一起写回
```

所以这个 ASR 没有再单独占一个普通 `S_RUN` 拍。

## worker1 后半段例子

worker1 后半段：

```asm
pc17: LDR   r5, A[1]
pc18: LDR   r6, A[5]
pc19: SMUAD r7, r6, r3
pc20: SMUSD r8, r6, r4
pc21: ASR   r7, r7, #7
pc22: PKHBT r9, r7, r8, LSL #9
pc23: SADD16 r10, r5, r9
pc24: SSUB16 r11, r5, r9
pc25: STR r10, B[1]
pc26: STR r11, B[5]
pc27: B .
```

执行节奏：

| 拍 | 主要动作 |
| --- | --- |
| 1 | `LDR r5,A[1]` 和 `LDR r6,A[5]` 双发 |
| 2 | `SMUAD` 在 `S_RUN` 启动 DSP，第一条做 `mul_s16_stage1` |
| 3 | `S_DSP_MUL`，第一条做 `mul_s16_stage2`，同时第二条做 `mul_s16_stage1` |
| 4 | `S_DSP_PAIR_MUL_ACC`，第一条做加减，第二条做 `mul_s16_stage2` |
| 5 | `S_DSP_PAIR_WB_ACC`，写回第一条 DSP，并准备 `ASR` 结果 |
| 6 | `S_DSP_PAIR_WB`，写回第二条 DSP 和 `ASR` 结果 |
| 7 | `PKHBT` |
| 8 | `SADD16` 和 `SSUB16` 双发 |
| 9 | `STR` 和 `STR` 双发 |
| 10 | `B .` 完成哨兵 |

## 写回和前递

为了避免读到旧寄存器值，worker 有写回前递。

普通写回：

```text
rf_wb_*
```

第二写回：

```text
rf_wb2_*
```

读取寄存器时会先看：

```text
有没有正在写回同一个寄存器
```

如果有，就直接用最新写回值。

这叫前递。

## 为什么需要前递

例子：

```asm
MOV r1, #91
PKHBT r3, r1, r1, LSL #16
```

`PKHBT` 紧跟着用 `r1`。

如果没有前递，可能读到旧的 `r1`。

当前设计会把刚写回的 `r1` 直接送给后续指令使用。

## 分支怎么处理

分支包括：

```text
B
BL
MOV pc, lr
```

分支发生时：

```text
清空当前错误路径上的 exec/dec 信息
关闭 pair_kind
pc_fetch_reg = branch_target
回到 S_FETCH
```

所以分支后不会继续执行旧流水里的错误指令。

## `B .` 完成哨兵怎么处理

执行到：

```text
0xEAFFFFFE  ; A32 B .
```

worker 按标准分支执行，把 PC 跳回当前字节地址。顶层不靠 worker 内部
伪停止 opcode，而是观察每个 active worker 的 `instr_debug` 是否到达这条
标准自跳转指令。

```text
worker_done_raw = (instr_debug == 0xEAFFFFFE) or illegal/halted fallback
```

四个 active worker 都被顶层寄存为 done 后，系统停止计数并开始 dump 输出。

## illegal 怎么处理

如果译码或执行发现非法指令：

```text
illegal = 1
halted = 1
```

系统会停止运行。

## 内存为什么不乱

单个 worker 内：

```text
LDR + LDR 双发使用两个读口
STR + STR 双发使用两个写口
STR + STR 要求 idx 不同
```

多个 worker 之间：

```text
没有动态仲裁
靠汇编调度保证同一拍不写坏同一个位置
```

数据 bank 采用副本方式：

```text
每个 worker 读自己的 bank 副本
写入时同步更新所有副本
```

这样可以降低读端口冲突。

## 一拍里到底谁优先

`S_RUN` 中大致优先级：

```text
1. 如果当前指令 illegal，停止
2. 如果 pair_kind 有效，执行双发射路径
3. 否则按单条 exec_op 执行
4. 如果是 DSP，进入 DSP 多周期状态
5. 如果是分支，刷新流水并跳转
6. 如果顶层看到 `B .` 完成哨兵，寄存该 worker done
```

注意：

```text
双发射和 DSP 配对不是一回事
```

普通双发射靠：

```text
pair_kind
```

DSP 配对靠：

```text
dsp_pair_ready
```

## 答辩说法

可以这样讲：

```text
我们的 worker 是一个小型多周期流水核心。普通情况下，执行级每拍执行一条，同时译码级和取指侧往前推进；如果 ROM 预译码确认相邻两条指令安全，就在同一个 S_RUN 中双发射；如果遇到 SMUAD/SMUSD，就暂停普通发射，进入 DSP 多周期状态。DSP 完成写回后再回到 S_RUN。整个过程由同一个 worker 状态机控制，所以不会出现流水、多发射、多周期同时失控的问题。
```
