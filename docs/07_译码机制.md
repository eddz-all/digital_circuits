# 译码机制

## 译码在哪里

| 位置 | 用途 |
| --- | --- |
| `mcu4_worker_decoder.vhd` | 独立译码器 |
| `mcu4_worker_instr_rom.vhd` | ROM 内部预译码 |

两处译码语义一致。

## 独立译码器输入输出

输入：

```text
instr_word
pc_index   -- 来自当前 32-bit PC 的 PC[7:2]
```

输出：

```text
op
rd
rn
rm
imm
idx
illegal
```

## 译码顺序

| 顺序 | 判断 | 结果 |
| --- | --- | --- |
| 1 | `[31:20]=E3A`, `Rn=0`, `rotate_imm=0` | A32 `MOV_IMM` |
| 2 | `[31:20]=E1A`, `Rn=0`, shift type `ASR` | A32 `ASR` alias |
| 3 | `[31:20]=E1A`, `Rn=0`, no shift | A32 `MOV_REG` 或 `NOP` |
| 4 | `[31:20]=E08`, no shift | A32 `ADD` |
| 5 | `[31:20]=E04`, no shift | A32 `SUB` |
| 6 | `[31:20]=E00`, no shift | A32 `AND` |
| 7 | `[31:20]=E18`, no shift | A32 `ORR` |
| 8 | `cond=E`, `[27:20]=68`, LSL form | A32 `PKHBT` |
| 9 | `[31:20]=E59`, `Rn=r0` | A32 `LDR` immediate |
| 10 | `[31:20]=E58`, `Rn=r0` | A32 `STR` immediate |
| 11 | `cond=E`, `[27:20]=61`, `[11:8]=F` | A32 `SADD16/SSUB16/SSAX` |
| 12 | `cond=E`, `[27:20]=70`, `[15:12]=F` | A32 `SMUAD/SMUSD` |
| 13 | `[31:24] = EA/EB` | `B/BL`；`EAFFFFFE` 也按标准 `B .` 译码 |
| 14 | 其他 | `illegal` |

这些判断对应 `Armv7-A/R AArch32 A32` 标准编码的本工程子集，不再使用旧版 `ED/EC/ECA/E3E` 自定义 DSP 编码。

## NOP 译码

```text
[31:20] = E1A
Rn = r0
shift = 0
rd = r0
rm = r0
```

译码结果：

```text
WOP_NOP
```

## LDR/STR 译码

先算：

```text
word_addr = imm12 / 4
```

再判断：

| word 地址 | 结果 |
| --- | --- |
| `16..23` | `bank0`，`idx = word_addr - 16` |
| `32..39` | `bank1`，`idx = word_addr - 32` |
| 其他 | `illegal` |

所以执行级看到的已经不是完整地址，而是：

```text
bank + idx
```

## 分支译码

```text
target_index = pc_index + 2 + sign_extend(imm24)
target_addr  = target_index * 4
```

如果 `target_index` 不在当前实现的 ROM 窗口 `0..63`：

```text
illegal = 1
```

执行级收到的 `imm` 是 32-bit 字节地址形式的 `target_addr`。因此 `B .`
的机器码 `0xEAFFFFFE` 译码为普通 `WOP_B`，目标地址等于当前 PC。

## ROM 预译码

`mcu4_worker_instr_rom` 不只输出指令字，还输出：

```text
dec_op
dec_rd
dec_rn
dec_rm
dec_imm
dec_idx
dec_illegal
pair_kind
next_pair_kind
```

当前上板版本在 ROM 里定义了预译码表项：

```text
worker_decode_entry_t
```

表项内容：

```text
op
rd
rn
rm
imm
idx
illegal
```

然后用：

```text
build_decode_rom
```

对每个 ROM 程序提前生成：

```text
FFT_DEC_W0
FFT_DEC_W1
FFT_DEC_W2
FFT_DEC_W3
SELFTEST_DEC
```

运行时 `pc_index` 选中某条指令，ROM 同时查出：

```text
instr_value
decode_value
pair_value
next_pair_value
```

这样 worker 不需要在执行级重新分析完整 32-bit 指令。

它仍然不是固定 PC 专用硬件，因为预译码结果完全来自 ROM 里真实的 32-bit 指令字。

## pair_kind

`pair_kind` 表示当前指令和下一条指令能不能双发。

| pair_kind | 含义 |
| --- | --- |
| `000` | 不能双发 |
| `001` | `MOV_IMM` + `MOV_IMM` |
| `010` | `LDR bank0` + `LDR bank0` |
| `011` | `LDR bank1` + `LDR bank1` |
| `100` | `STR bank0` + `STR bank0` |
| `101` | `STR bank1` + `STR bank1` |
| `110` | `SADD16` + `SSUB16` |

## 双发条件

| 双发类型 | 条件 |
| --- | --- |
| `MOV_IMM` + `MOV_IMM` | `rd` 不同 |
| `LDR` + `LDR` | 同 bank，`rd` 不同 |
| `STR` + `STR` | 同 bank，`idx` 不同 |
| `SADD16` + `SSUB16` | `rn/rm` 相同，`rd` 不同 |

## worker 怎么用译码结果

```text
S_FETCH  ：从 ROM 取指令和预译码字段
S_DECODE ：把预译码字段送入执行级
S_RUN    ：按 op 执行
```

如果 `pair_kind` 有效：

```text
当前指令用 exec_* 字段
下一条指令用 dec_* 字段
一拍执行两条
PC += 8 bytes
```

如果 `pair_kind` 无效：

```text
只执行当前指令
PC += 4 bytes
```

## 非法指令

以下情况会置 `illegal`：

```text
未知 opcode
访存地址不在 bank0/bank1 范围内
分支目标不在当前 64 条指令 ROM 窗口
当前 A32 子集之外的指令形式或子字段不支持
```

worker 遇到非法指令后停止。

## 一句话答辩说法

```text
我们的译码不是完整 ARM 译码，而是对本工程使用的 Armv7-A/R AArch32 A32 标准编码子集做固定识别；ROM 同时做预译码和双发射判断，worker 执行级直接使用 op、寄存器号、立即数和 bank idx。
```
